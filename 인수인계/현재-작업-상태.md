### 사이트 이름과 메뉴 구조 개편 (2026-10-31, 로컬 확인 단계)

- 사이트 이름을 **Amplify 배움공방**으로 확정했습니다. 상단 로고·푸터·페이지 제목·개인정보 안내 본문에 적용했고, 도메인(betterwithu.kr)·GitHub 계정/레포·이메일은 그대로입니다.
- 상단 메뉴는 모든 페이지에서 `제작 도구(index.html#tools) · AI 스킬(ai-skill.html) · CL 학습자료(cl.betterwithu.kr)` 세 개입니다.
- 제작 도구 = 글자 꾸미기, 수식 입력. 수식 입력 페이지(`math.html`) 안에 "웹에서 해보기(`convert.html`)"와 "스킬 설치(`skill.html`)" 두 카드가 나란히 있습니다.
- AI 스킬 = 신규 `ai-skill.html`(스킬 설명 + 수식 입력 스킬 카드 → `skill.html`, CL 해석 스킬 카드 → `interpret.html`). 홈의 `interpret.html` 카드와 "AI 사용 설정" 배너는 없앴습니다.
- `settings.html`·`gemini-key.html`은 `convert.html` 쪽에서만 들어갑니다. `skill.html` 주소는 그대로입니다.
- 같은 날 CL 해석 스킬 안내를 수식 스킬 안내와 같은 틀로 개편했습니다. `interpret.html`(허브)과 `interpret-claude/chatgpt/gemini.html`(AI별)이 있고, 사이트 복사본 `skill/cl-interpreter/`와 `skill/cl-interpreter.zip`(저장소 v0.3.2, 14개 파일)을 새로 두었습니다.
- **CL zip은 ChatGPT 웹(Plus)에서 올려 등록되는 것을 사용자가 확인했습니다(2026-11-01). Claude·Gemini에는 올려 본 적이 없고, 올린 뒤 풀이 품질도 확인하지 못했습니다.** 지식 파일이 약 126KB(zip 기준)로 수식 스킬(약 20KB)보다 훨씬 커서 일부만 읽힐 수 있다는 저장소 안내도 페이지에 옮겨 두었습니다.
- 수식 스킬의 "붙여넣기" 방법은 CL 스킬에 그대로 쓸 수 없어 "지침(`instructions-short.md`) 붙여넣기 + 지식 파일 올리기"로 바꿨고, 이것도 직접 확인하지 못했습니다.
- ChatGPT는 **GPT 만들기가 종료**됐습니다(2026-10-31 사용자가 Plus 계정에서 확인: "이제는 GPT를 만들 수 없습니다", "GPT는 12월 11일에 종료됩니다"). 그래서 CL 스킬 안내에서 "맞춤 GPT로 쓰기"를 삭제했고 ChatGPT는 zip 업로드만 안내합니다. 무료 계정은 스킬 화면에 "이 계정에서는 스킬을 사용할 수 없습니다"가 나와 방법이 없습니다(Claude·Gemini 권장).
- ChatGPT 웹 채팅에 "이 GitHub 저장소의 스킬을 내 ChatGPT 스킬로 설치해 줘"라고 보내면 "외부 GitHub의 스킬을 스킬 목록에 직접 등록하는 기능은 없다"고 답하고 설치하지 않습니다(2026-11-01 사용자 확인). ChatGPT 앱의 Work에서 같은 요청을 해도 저장소를 zip(`cl-interpreter-skill-날짜.zip`)으로 압축해 줄 뿐 스킬로 설치하지 않았고, 종료된 "GPT 만들기 → 지식 → 파일 올리기" 방법을 안내했습니다(2026-11-01 사용자 확인). 그래서 채팅·Work 설치 방식은 안내하지 않습니다. **CL 스킬의 ChatGPT 안내는 "유료 계정(Plus 이상)의 zip 업로드"와 "Codex(터미널)로 설치(②)" 두 가지**입니다. 수식 스킬 안내(`skill-chatgpt.html`)는 무료에서도 되는 붙여넣기가 있어 그대로 둡니다. 같은 유료 계정에서 **웹은 zip 업로드·등록이 되지만 ChatGPT 앱(데스크톱)에는 업로드 메뉴가 없습니다**(2026-11-01 사용자 확인). 두 ChatGPT 안내에 "웹 브라우저에서 해 보세요"를 넣었습니다. 서비스 메뉴는 자주 바뀌므로 안내문은 단정 대신 "확인했을 때는 …"·"…할 수 있습니다"로 씁니다(사용자 요청).
- Gemini의 Gems는 2026-11-17부터 스킬로 바뀝니다. CL 안내의 "Gem으로 쓰기"가 그 뒤에도 되는지 확인하지 못했으니 11월 17일 이후 다시 점검하세요. Claude "프로젝트로 쓰기"도 직접 확인한 적이 없습니다.
- 저장소 안내(`guides/install-gpt.md`, `install-gemini.md`)의 지식 파일 목록에는 v0.3.2에서 추가된 `reference/unverified.md`가 빠져 있습니다. 사이트 안내는 이 파일을 포함해 reference 3개로 적었습니다.
- 이 변경은 아직 commit·push·배포하지 않았습니다.

## 확정된 제품 방향

- 사용자의 주목적은 수업자료 제작 도구이고 CL 학습자료는 그 다음입니다.
- AI가 필요 없는 도구는 글자 꾸미기와 수식 입력입니다.
- AI가 필요한 도구는 수식 변환 하나입니다. CL 코드 분석은 웹 도구에서 스킬 배포로 전환했습니다(2026-10-21).
- 두 AI 도구는 한 번 저장한 동일한 Gemini 설정을 사용합니다.
- 각 사용자가 Google AI Studio에서 개인 키를 발급받아 쓰는 것이 기본입니다.
- 운영자 공유 키와 공유 암호는 연수 시연·초기 체험용입니다.
- 서울대 별도 API와 OpenAI·Claude 제공자는 현재 제품 범위에 추가하지 않습니다.

## 다음 작업

가장 가까운 후속 작업은 **배포본에서 Gemini 안내 동선과 실제 개인 키 호출을 확인하는 것**입니다.

- `settings.html`과 수식 변환기 도움말에서 `gemini-key.html`로 이동하는지 확인합니다.
- 안내 페이지에서 공식 Google AI Studio가 새 탭으로 열리는지 확인합니다.
- 실제로 새 키를 만든 직후의 복사 화면과 왼쪽 아래 `Get API key` 버튼 동작은 아직 확인하지 못했습니다.
- 유효한 개인 키로 수식 변환이 작동하는지 확인합니다.

## 알려진 제한과 확인할 사항

- `api/ai.js`의 메모리 기반 실패 제한은 서버리스 인스턴스 전체를 아우르는 영구 제한이 아니라 보조 방어입니다.
- 실제 Gemini 호출은 유효한 개인 키 또는 운영 공유 암호로 다시 확인해야 합니다.
- `GEMINI_API_KEYS`에 같은 Google Cloud 프로젝트의 키를 여러 개 넣어도 프로젝트 단위 할당량은 늘어나지 않습니다.
- Vercel의 `SHARE_PASSWORD`, Gemini 키와 모델 값은 저장소에서 확인할 수 없습니다.
- README나 과거 Git 기록에 있었던 암호 예시는 이미 폐기된 것으로 취급하고 재사용하지 않습니다.
